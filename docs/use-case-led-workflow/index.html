The product decision

Add intelligence upstream. Preserve truth downstream.

The current repository already has the correct approval, hashing, architecture, build, connection, and verification spine. Replacing it would create migration risk without improving the human task. The proposal adds a richer authoring model and compiles it into today’s stable contracts.

Division of labor

Humans make consequential judgments. The tool does the clerical analysis.

The experience is exception-led. If context is coherent, the user sees a draft, a tiny decision inbox, and an approval summary. Technical detail stays one click away for architects, regulated review, and debugging.

Explainable architecture

A solution map users can understand and safely reshape.

The proposal starts with the least distributed architecture that satisfies the approved stories and quality drivers. Every boundary must have a reason; every story must have a path; every external actor must have a technology-neutral port and a concrete adapter decision.

Implementation sequence
